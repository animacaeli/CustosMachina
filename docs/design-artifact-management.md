# 制品管理（产物型项目支持）·设计预案（暂缓）

> 定稿：2026-10-07（对话评估定调；用户裁定：**提前设计、暂缓开发**，判据触发后再立项）
> 性质：暂缓预案，非当前排期项。P8 终局定位「按需小项走判据触发」（roadmap §四-B）的第一份备档。
> 背景：评估 Android / iOS / Wails v3 / 微信小程序等**产物型项目**（交付安装包而非可部署服务）
> 接入平台 CI/CD 的兼容性，结论为当前不兼容，缺口结构性存在，故留此预案。

## 一、问题定义与现状结论（2026-10-07 代码核实）

产物型项目四类形态：

| 类型 | 产物 | 构建侧要点 | 分发侧要点 |
|---|---|---|---|
| Android | apk / aab | Jenkins + SDK 镜像，无障碍 | 下载页/分发渠道 |
| iOS | ipa | **需 mac 构建节点**，签名链路 | 下载页/分发渠道 |
| Wails v3 桌面端 | dmg / exe / msi | Jenkins + 各 OS 工具链 | 安装包分发（后续可做更新 feed） |
| 微信小程序 | 版本回执/预览码 | 构建后 `miniprogram-ci` 上传+提审 | 记录回执与预览码，无安装包下载 |

现状三缺口：

1. **CI 纯观测，无产物概念**：`CIProvider` 仅 `Status`/`Log`
   （`backend/internal/modules/ci/provider.go:64`），构建由 gitee webhook 驱动 Jenkins，
   平台不做 CI 控制面（plan-phase6 M8 裁定）。四类项目**照常在 Jenkins 构建、平台可看状态与日志**，
   但 Build 模型无 artifact 字段（`ci/model.go:27-46`），无版本归档、无下载入口。
2. **发布强绑定服务部署**：三重硬校验（BuildSuccess 门禁 / 部署目标 / compose 文件，
   `release/service.go:146-236`），无「仅登记版本、不部署」模式；蓝绿/灰度/回滚对客户端产物无意义。
3. **产物概念是当初主动排除项**：plan-phase4-runtime.md:62「编译型语言不需要独立产物——
   同一业务镜像 + 子命令」。本预案不推翻该裁定（服务端项目维持现状），只补**增量场景**。

可复用件盘点（预案可行性依据）：

- 备份 storage 抽象（`backup/storage.go:21-26`：Put/List/Delete，local + S3 兼容双实现，minio-go）
  ——**补一个 Get 接口即有下载能力**；七牛 Kodo S3 兼容端点可直接接入。
- SFTP 任意文件上传/下载（`resources/sftp.go`，100MB 上限，下载走既有 ticket 机制）。
- M5 应用级 token 先例（`POST /api/notify/business`）——构建机脚本回传产物的鉴权可复用。
- 90 天保留期清理机制模式（备份、cron_runs 生命周期同源）。
- cron 一次性容器化脚本（可在资源主机跑构建辅助任务，需自备镜像；
  iOS 签名不适合容器沙箱模型，不依赖此路径）。

## 二、启动判据（何时立项）

满足其一即立项（主判据优先）：

1. **第一个真实产物型项目确定接入平台管理**（主判据）；
2. 版本台账/追溯出现明确的协作或合规需求（弱判据）。

判据未满足期间维持**零开发观测层用法**：构建全在 Jenkins 侧，平台看状态 + 日志 + 构建通知，
产物在 Jenkins / 分发渠道侧自取。此用法今天即可用，无任何阻塞。

## 三、方案：最小闭环（立项时的既定边界）

1. **Build 挂产物列表**（一对多，支持多文件：apk+aab / 多架构安装包 / 预览码图片）：
   文件名、大小、sha256、入库时间；保留期默认 90 天，复用既有清理模式。
   **版本台账 = Build 记录本身**（tag/状态/时长已有），不新立版本模型、不动 Release。
2. **产物获取只做 Jenkins API 拉取**（archiveArtifacts）一条路：gitee+Jenkins 是主力组合
   （P6 M8 适配）。构建机脚本回传（M5 应用级 token + 上传端点）列为后补项，首版不做。
3. **存储复用备份 storage 抽象 + 补 Get 接口**：local / S3 双后端同时受益；
   不引入 Nexus/Harbor 等重型制品库（轻量红线）。
4. **UI**：构建抽屉加产物 tab（列表 + 大小 + sha256 + 下载按钮），下载走既有 ticket 机制。
5. **端侧不特化**：iOS 的 mac 构建机与签名全留 Jenkins 凭据体系，平台无感知；
   小程序 `miniprogram-ci` 上传提审留在流水线脚本内，平台只挂回执文件（预览码二维码 = 任意文件）。

## 四、明确不做（沿用平台定位，防蔓延）

- **发布模型改造**（产物型项目跳过 compose 校验 / Release 退化为版本登记）——Build 即台账，不动发布主链。
- **iOS 证书/描述文件托管**——签名链路安全复杂度过高，留在 Jenkins 凭据。
- **商店自动提审编排**——小程序提审是流水线脚本行为，平台不编排。
- **自建构建执行器**——平台不做 CI 控制面（plan-phase6 M8 已裁定，本预案不改）。
- **重型制品库**（Nexus/Harbor）——违反单实例轻量定位。

## 五、预留决策点（立项时裁定，当前仅记倾向）

| # | 决策点 | 倾向 |
|---|---|---|
| D1 | 产物拉取时机：CI 终态轮询时自动拉 vs 构建抽屉手动触发 | 前者（复用 poller 终态钩子，Jenkins 侧 artifact 就绪即入库） |
| D2 | 单文件大小上限：SFTP 先例 100MB，ipa/桌面安装包可能超 | S3 路径放宽至 1GB，local 后端按磁盘余量告警 |
| D3 | 保留期能否按项目覆盖 | 支持（项目级可选覆盖，缺省 90 天） |
| D4 | Jenkins 拉取凭据：复用 CI 现有 Jenkins 配置 vs 单独配置 | 复用（同一 provider 实例，不新增凭据面） |

## 六、量级评估

R1 级别小里程碑（1~2 周）：后端 artifact 表 + Build 关联、Jenkins artifact 拉取、
storage 补 Get、下载路由、保留期清理、版本化 migration；前端一个产物 tab。
不动发布主链（release/蓝绿/灰度/k3s 零改动），风险接近零。发版随 v0.12.x 小版本。

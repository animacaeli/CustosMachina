# 第五阶段计划：平台横切服务与 AI 地基（统一通知路由 / 备份恢复 / 观测告警闭环 / 配置文件管理 / 证书自动续期 + AI 中转试点）

> 状态：**已定稿并开工**（v1.1，2026-10-02 讨论稿当日评审通过；附加执行约定：需在服务器部署的组件（如 O2）一律走平台项目部署链路，不直接操作服务器——dogfood 优先）
> 范围决策记录：**证书 lego 进 P5**；AgileConfig 接入、堡垒机补齐**顺延 P6**；安全欠账**随 M1 分散清**（不压收尾）；AI 顾问试点**只做告警诊断摘要**（变更审核建议顺延 P6 与对话 UI 会师）。
> 上游依据：docs/roadmap.md 第三节（P5）、第五节（AI 规划）、第六节（生态抽象纪律）。
> 本阶段要回答的三个问题：
> 1. **横切服务在"单实例轻量"约束下做到什么程度**——通知/备份/证书/配置哪些收敛为平台服务，哪些明确止步？
> 2. **AI 五条铁律如何落成代码**——中转层 + Context Pack 只读版（角色过滤 + DLP）在 P5 的最小可信实现是什么？
> 3. **裁剪线如何执行**——时间不够时按序保 M1→M2→M3（通知 → 备份 → 告警），M4~M6 顺延 P6 不跨阶段阻塞。

## 一、总判断：P5 是"服务化"阶段

P1~P4 把资源、环境、运行时做成了**功能**；P5 把功能之间共用的能力收敛为**服务**：

- 通知：从"cron/observ 各自直推运维群"收敛为统一路由（规则 + 聚合 + 静默）；
- 数据：从"无备份"到"可恢复"（含平台自身备份与演练）；
- 观测：从"组件部署"到"告警闭环"（O2 告警 → 平台路由 → IM）；
- 配置：从"编辑器能力"到"文件真相源"（存储/版本/审计/下发/生效）；
- 证书：从手工（遗留 #16 生产 HTTPS 未配）到自动续期发放；
- AI：铺中转层与 Context Pack 只读版（P6 主线的地基，本阶段仅 advisory 一个场景）。

**依赖图与顺序理由**：

```
M1 统一通知路由 ──┬──> M2 备份(失败通知)
                  ├──> M3 O2 告警(事件出口) ──> M6 AI 告警诊断摘要
                  ├──> M5 证书(到期告警)
                  └──> (M4 配置文件·独立，仅复用 SSH/Monaco/casbin)
```

M2/M4 相互独立可并行；M6 必须在 M3 之后（依赖告警事件流）。建议周期 5~6 周。

## 二、里程碑

### M1 统一通知路由 + 安全欠账清偿（约 1 周）

**现状锚点**：notify 模块已有 `notify_groups`（webhook 群 + provider 探测 + ops 群概念）与发送节流；cron / observ 失败目前**直推**，没有规则层。

**模型（防膨胀边界：不做升级链/值班表/多渠道编排/去重持久化）**：

- `notify_rules`：事件源（`cron_failed` / `observ_failed` / `o2_alert` / `cert_expiring` / `backup_failed` / `ai_digest`）、级别（info/warn/critical）、目标群、静默时段（起止时钟点，跨零点合法）、聚合窗口分钟数（同源同类窗口内聚合为一条，内存态即可——单实例）、启用开关；
- 事件入口 `NotifyEvent(source, level, dedupKey, title, body)`：dedupKey 供聚合；无匹配规则时落默认群（保底知情权）；
- 存量改造：cron / observ 的直推改走 NotifyEvent，行为不变（默认规则等价旧行为）。

**安全欠账（同批清偿，均为小项）**：

1. 登录限速：`/auth/login`、`/auth/qrlogin/url|exchange|callback`、`/setup/*` 公共接口按 IP 限速（内存滑动窗；已配置 Redis 则用 Redis）；
2. 时序侧信道：用户不存在时预跑 dummy bcrypt 拉平登录耗时；
3. CORS：通配 `*` 收敛为 `CUSTOS_CORS_ORIGINS` 白名单（未配置 = 仅同源）。

**验收标准（可判定）**：

- cron 任务失败 → 按规则路由到指定群；同类失败 5 分钟窗口内聚合成一条（真机两连败只收一条）；
- 静默时段内 critical 仍投递、warn 被静默；
- 同 IP 对 `/auth/login` 连续 10 次失败后返回 429 并锁定 10 分钟；
- 用户名不存在与密码错误两种路径的响应耗时差 < 50ms（脚本实测）；
- 白名单外 Origin 的预检/请求被拒。

### M2 备份与恢复（约 1 周）

**模型**：

- `backup_jobs`：名称、类型（`platform-self` / `remote-db` / `remote-dir`）、目标（SSH 主机+路径，或 S3：endpoint/bucket/prefix + AES 凭证）、cron 表达式（复用 cron 调度）、保留个数；
- `platform-self`：SQLite 数据文件（或 mysql dump）+ `/data` compose 目录 + 密钥导出；
- S3 兼容直连（MinIO SDK，云 OSS / 阿里 OSS 通吃，**不做多适配抽象**）；
- 执行历史复用 cron_runs 生命周期模式（状态/输出/保留期清理）；
- 恢复：`deploy/restore.sh` 一键脚本 + 演练文档。

**设计决策点（实现前定死）**：平台自身备份的密钥导出口令方案——无口令则 master key 明文入备份包（UI 必须显著警示），或强制备份口令加密（恢复时输入）。默认取**强制口令**，代价是恢复多一步。

**验收标准**：

- 新空机用备份产物 + restore.sh 拉起平台：登录可用、既有项目/主机/用户数据完整（演练实测并留档过程）；
- 备份失败经 M1 路由告警，1 分钟内 IM 送达；
- 保留策略生效：超限自动清理最旧备份（造 3 份验证）。

### M3 O2 观测闭环 + 告警（约 1.5 周）

- 告警模板自研 UI：平台侧 CRUD，调 O2 alerts API 同步（**前置调研 2 天**：O2 `/api/{org}/alerts` 覆盖度；不足则降级"外链 + 文档指引"）；
- 告警事件流：O2 告警的 destination 指向平台 `POST /api/observ/alerts/webhook` → `NotifyEvent(o2_alert, ...)`；
- 日志/仪表盘外链 + 透传认证（O2 会话半小时）；
- 补 P4 遗留：vector→O2 实际投递验证（真机日志可查）；
- **ObservBackend 不抽接口**（rule of two：唯一实现；Grafana/Loki 需求出现再抽）。

**验收标准**：

- O2 告警触发到 IM 送达 ≤ 30s（真机实测）；
- 模板在平台创建 → O2 侧可见 → 真实触发 → 通知全链路打通；
- 外链免登点入对应日志流；
- vector 采集的业务日志在 O2 可检索。

### M4 配置文件管理（约 1 周，独立模块）

细则按 roadmap §2 定稿执行，要点落地：

- `config_files`：项目/主机绑定、目标路径、类型（yaml/json/toml/env）、当前内容、敏感标记；
- `config_versions`：全量快照 + hash + 来源（手动编辑/下发回写）；
- 下发：SFTP 写入前备份旧文件（`.bak.{unixts}`）→ 落审计事件；
- 生效动作（可选三型）：SIGHUP / 调用 refresh 端点 / 重启容器；未配置监听的应用走重启——**热更边界在 UI 明示**（平台不承诺 SDK 级热更）；
- UI：独立一级菜单"配置管理"（参考三阶段 projects 独立先例），Monaco 多语言编辑、版本 diff 对比、敏感文件默认脱敏（明文查看需 admin + 审计）；
- casbin 资源点 `config_file:*`；文件真相源归本模块，K/V 拉取式归 AgileConfig（P6）。

**验收标准**：

- 修改 → 下发 → SFTP 落盘 → 一键回滚旧版本（真机各一例）；
- 敏感文件默认脱敏展示，admin 查看明文留审计记录；
- 三型生效动作各真机验证一例（SIGHUP 生效 / refresh 200 / 容器重启完成）。

### M5 证书自动续期（约 0.5~1 周）

- `certs`：域名列表、DNS provider（lego 内置全量，不自研）、签发状态/到期时间、部署目标（主机 + nginx conf 路径 + 是否 reload）；
- 调度：复用 cron（到期前 30 天自动续期任务，仅手动兜底触发）；
- 发放：SSH 上传证书 → `nginx -t` 通过才 reload（失败告警走 M1）；
- 消化遗留 #16：dogfood 域名（custos-machina.animacaeli.site）真机签发。

**验收标准**：

- ACME staging 全流程：签发 → 部署 → HTTPS 生效 → 到期前自动续期演练；
- `nginx -t` 失败时不 reload 且告警送达（注入坏配置验证）。

### M6 AI 中转层 + Context Pack（只读）+ 告警诊断摘要（约 1.5 周）

- **中转层**（`internal/modules/ai` 已占位）：OpenAI 兼容协议代理；provider/endpoint/model/key（AES 落库）；用量记录 + 审计；后端中转铁律第一条落地；
- **Context Pack v0（只读）**：pack 组装器按事件打包——告警事件 + 关联主机近期指标 + 近期 cron/发布记录 + 项目配置快照（脱敏后）；
  - **角色过滤**：pack 组装按调用者角色裁剪（dev 的 pack 不含 prod 明文配置与全量日志）；
  - **DLP 清单**：凭据/token/ticket/手机号等模式黑名单，启动时校验清单完整性、入 pack 前逐块拦截（拦到即替换为 `[REDACTED]` 并记审计）；
  - pack 内容以"不可信输入"数据块包裹（prompt 注入对策的第一处落地点）；
- **告警诊断摘要**：M3 的 o2_alert 事件 → pack → 中转层 → 摘要作为告警通知附注，显著标注"AI 建议（参考）"；未配置 AI 时优雅降级为纯通知。

**验收标准**：

- 告警通知附 AI 摘要（真机）；
- DLP 用例测试：注入假凭据/手机号的日志进 pack 后全部被 `[REDACTED]`（单测覆盖每类清单项）；
- dev 角色组装的 pack 断言不含 prod 配置明文（单测）；
- 中转层对无效 key / 超限有明确错误语义与用量落库。

## 三、明确不做（本阶段防蔓延）

AgileConfig 接入（P6）、堡垒机补齐（P6，含 #20/#38 审计回放）、通知升级链/值班表/多渠道编排、AI 对话 UI 与 SSE（P6 首项，动手前一页技术设计文档先行）、NL→操作（P6 确认层）、ObservBackend / ConfigProvider 抽象、多配置中心生态、链路追踪、平台多实例 HA。

## 四、开源适配层审视（rule of two 逐项判定）

| 本阶段触点 | 判定 |
|---|---|
| M2 对象存储 | S3 协议标准直连（MinIO SDK），不抽接口 |
| M3 观测后端 | 只写 O2 具体实现；ObservBackend 等 Grafana/Loki 需求出现再抽 |
| M5 ACME DNS | lego 内置全量 provider，不自研 |
| M6 模型接入 | OpenAI 兼容协议即标准（自托管小模型与云 API 通吃），不抽多 provider 接口 |
| GitProvider | 本阶段不动；P6 开源化批次再评估 |

## 五、欠账消化安排

- **M1 同批清**：登录限速（含扫码公共接口节流）、登录时序侧信道、CORS 通配收敛（roadmap 指定的 P5 必清项）；
- **继续挂账**：slot_overrides 配置中心接管（随 AgileConfig 顺延 P6）；#20/#38 终端审计回放（随堡垒机顺延 P6）；#33 前端 composable 抽取（P6 技术债批次）；版本化 migration（P6 开源化前置项）。

## 六、风险与前置调研

| 风险/调研 | 时点 | 缓解 |
|---|---|---|
| O2 alerts API 覆盖度不明 | M3 开工前 2 天 | 不足则告警模板降级"外链 + 文档指引"，事件流只收 O2 主动告警 |
| 备份口令方案体验（恢复多一步） | M2 设计点 | 默认强制口令；文档写明权衡 |
| 企微通知 markdown/长文截断兼容（聚合与 AI 摘要格式） | M1 内半天调研 | 摘要超长折叠为"详情见平台"链接 |
| AI 输出质量不可控 | M6 | advisory 定位 + 固定模板 + 明显"AI 建议"标注；不做任何自动执行 |
| 阶段超期 | 持续 | 裁剪线：按序保 M1→M2→M3，M4~M6 顺延 P6 |

## 七、执行与验收纪律

- 沿用 P4 质量闭环：里程碑实施 → 深审 → 真机 + UI 双验证 → 收尾评审；
- 每里程碑合入 main 即滚动发版（语义化递增），阶段收尾做总结评审并更新 roadmap；
- 所有新表/新资源点过 casbin 三级角色矩阵评审；新公开接口一律带限速审视。
